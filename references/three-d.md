# 3D (Three.js): 결정적으로, 설명하는 데에만

3D는 **물리적이거나 공간적인 무언가를 설명할 때만** 쓴다 (제품이 어떻게 생겼나, 사진이 어디서 찍혔나, 레이어가 어떻게 쌓였나). 타이포·리포트·폼은 선명한 HTML/SVG로 둔다. 가장 큰 개선은 3D를 더 넣은 것이 아니라 3D가 **설명하게** 만든 것이었다. 글자 돌출만 필요하면 kit `depthText`로 충분하다 ([motion-craft.md](motion-craft.md) "3D와 셰이더").

HyperFrames 쪽 연결 방법은 `hyperframes-animation/adapters/three.md`가 정본이다. 이 문서는 그 위에서 지켜야 할 원칙이다. 출처: [motion-video-kit](https://github.com/echris6/motion-video-kit) `three-js-patterns.md`, `product-hero-realism.md`(MIT).

## 렌더 계약: 모든 상태는 시간의 순수 함수

```js
export async function createScene(canvas) {
  const renderer = new THREE.WebGLRenderer({ canvas, alpha: true, antialias: true, preserveDrawingBuffer: true });
  renderer.setPixelRatio(1); renderer.setSize(1920, 1080, false);
  renderer.outputColorSpace = THREE.SRGBColorSpace;
  renderer.toneMapping = THREE.ACESFilmicToneMapping;
  // ...모든 것을 한 번만 만든다...
  function pose(t) { /* 모든 변환을 t로만 계산 */ }
  function render(t) { pose(t); renderer.render(scene, camera); }
  function anchors(t) { pose(t); return points.map(project); } // HTML 오버레이용 화면 좌표
  await renderer.compileAsync(scene, camera); render(0);
  return { render, anchors };
}
```

- 루트 타임라인이 seek·업데이트마다 `render(localTime)`을 부른다. **RAF 루프, `Date.now()`, 시드 없는 난수, 물리 이력 금지.** 어느 프레임으로 seek해도 같은 픽셀이어야 한다.
- 재타이밍은 영상 시간 → 로컬 시간 매핑(`(t - start) * speed`)으로만.
- 텍스처·폰트를 모두 로드한 뒤 resolve한다.
- 라벨·핀·리더 라인은 HTML/SVG로 두고, `anchors(t)`가 주는 투영 좌표로 매 프레임 위치를 다시 계산한다. 앵커에 정확히 붙는 것보다 **라벨 간격이 균등한 것**이 더 중요하다.
- 컷 양쪽이 같은 포즈를 계산하도록 공유 함수(`applyPose(u)`)를 쓰고, 컷마다 이웃 프레임과의 평균 프레임 차로 확인한다.

## 랩 먼저

3D 장면·커스텀 컴포넌트는 영상에 넣기 전에 **단독 컴포지션**(`<project>/lab/<name>/`)으로 만든다. 의미 있는 시점의 정지 3장 + 3–4초 모션 증명을 렌더해 [critic-loop.md](critic-loop.md) 컴포넌트 크리틱의 KEEP을 받은 뒤 합류시킨다. G3에서 가장 많이 틀어지는 구간이 3D다.

## 효과 있었던 패턴

- **분해 레이어.** 물체를 자기 로컬 좌표계에서 만들고 실제 레이어를 별도 그룹으로 쌓은 뒤, 법선 방향으로 서로 다른 양만큼 들어 올린다. 이징은 smootherstep(`x*x*x*(x*(x*6-15)+10)`), 스태거는 레이어당 5ms 이하. **cubic ease-out은 시작 속도가 최대라 한 프레임 팝이 생긴다.** 들어 올린 뒤에는 +10–15% 느린 "호흡" 분리로 홀드가 정지 화면이 되지 않게.
- **맥락에 꽂힌 사진.** 카메라가 모델 주위를 돌고, 기록된 지점이 보이는 순간 실제 사진 카드가 핀에서 튀어나와 리더 라인을 달고, 레일로 도킹한 뒤, 다음 장면 레이아웃의 정확한 픽셀 사각형으로 날아간다. 핀은 카메라 쪽 면에, 라벨은 사진 내용과 일치하게.
- **옵션 패치.** 픽셀 공간 직교 카메라(`OrthographicCamera(-960, 960, 540, -540)`)로 3D 패치가 HTML 카드 안에 정확히 앉게. 옵션마다 끝 상태가 분명히 다르게, 공중에 뜬 조각은 한 번에 하나.
- **물리 로고.** 베벨 조각이 마크로 조립된 뒤 같은 캔버스가 CSS transform으로 최종 락업 위치로 이동한다. 마크가 엔드 카드까지 살아남는다.

## 실제 제품처럼 움직이게 (히어로 모션)

- **참조 모션을 프레임 단위로 잰다.** 브랜드 자체 영상을 학습용으로만 받아 10·30fps로 타일링하고, 내 렌더도 같은 fps로 타일링해 나란히 비교한다. 움직이는 부분의 투영 폭으로 프레임당 각도를 추정해 키(초 → 각도)를 적는다. 실제 폴더블 펼침은 0→180°가 약 0.8초, 30–60°에서 가장 빠르고 엣지온 근처에서 머문 뒤 부드럽게 착지했다. **smoothstep이 아니다.**
- 키는 **단조 3차 보간(Fritsch–Carlson, 양 끝 기울기 0)**으로 잇는다. smoothstep을 섞어 "부드럽게" 했더니 머무는 지점이 옮겨지고 중간에 딸꾹질(7.8 → 2.6 → 5.4°/프레임)이 생겼다. 프레임당 각속도는 한 번 정점을 찍고 머물러야 한다.
- **모션 중에는 카메라를 고정한다.** 접촉 프레임에서 멈추는 리프레이밍은 카메라 흔들림으로 읽힌다. 리프레이밍은 착지 뒤로. 실제 자석 닫힘은 접촉 후 약 17프레임 동안 픽셀 단위로 정지다 (22px 흔들림, 1.7° 반동은 가짜로 읽혔다).
- **화면이 사실감의 절반이다.** 움직이는 동안 화면은 흐려져도 켜져 있고, 펼친 화면의 반쪽은 접힌 화면이 보여주던 것과 픽셀 단위로 같아야 한다 (작은 화면 텍스처를 큰 화면의 크롭으로 만들면 구조적으로 보장된다).

## 모션 블러

- 결정적 누적 방식: 셔터 안에서 N개 서브프레임(`t + ((i+½)/N − ½)·shutter`)을 렌더해 half-float 타깃에 평균. 여전히 t의 순수 함수.
- 빠른 가장자리에 서브프레임 10개는 빗살(±20 luma)이 보였다. 가장 빠른 0.5초 구간에 24개.
- 셔터 180°는 실제 영상 옆에서 너무 선명했다. 가장 빠른 구간 약 300° → 180°로 복귀.
- 블러 구간 경계에서 셔터를 약 6프레임에 걸쳐 0→최대로 올린다. 한 프레임에 켜지면 밝기 계단이 생긴다.
- 프레임당 30px 넘게 움직이는 빠른 동작은 전부 블러가 필요하다.

## 사실감 체크리스트 (크리틱이 지적한 것)

- ACES 톤 매핑은 배경색을 바꾼다. **렌더된 픽셀을 재서** 브랜드 토큰과 맞을 때까지 HDR 배경(선형 RGB에 채널별 1.1–1.9배)으로 보정한다. 포그도 같은 색.
- 건축 모형("마케트") 스타일이 어설픈 가짜 실사보다 고급스럽게 읽힌다.
- 장난감 티: 떠 있는 부품, 기둥처럼 보이는 사각 홈통, 평평한 검은 유리(색을 올리고 환경 반사 추가), 열린 이음새.
- 조명: 밝히고 싶은 쪽에서 부드러운 키 라이트, 들어 올린 레이어가 읽히는 그림자, 따뜻/차가운 림. 각도 변화를 알려 주는 유리 반사는 60% 이상 남긴다. 한 프레임 번쩍임은 조명을 어둡게 하지 말고 **넓혀서** 고친다 (빛 띠 폭 3 → 12, 낮은 출력).
- 카메라: 피치 35–55°, 최소 거리 유지 (큰 텍스처 평면을 수직으로 내려다보면 반복이 보인다), 롤 없음, 판 위에서 타이트하게 끝내지 말고 풀백.
- 1.5배 픽셀 비율로 렌더해 브라우저가 다운샘플하게 하면 계단이 줄어든다 (렌더 시간과 교환).
- 헤드리스 Chrome은 `-apple-system`을 Times로 렌더한다. 폰트는 `@font-face`로 로컬 파일에 묶는다.

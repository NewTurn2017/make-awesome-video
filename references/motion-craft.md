# 모션 크래프트: 모션 디자인이 "프로"로 읽히는 원리

HyperFrames 공식 스킬은 개별 기법(룰·블루프린트)을 준다. 이 문서는 그것들을 **한 편의 작품으로 엮는 감독의 원칙**이다. `motion`·`social` 모드에서 샷 리스트를 쓰기 전에 읽는다.

## 1. 모티프 연속성

프로 작품에는 **컷을 넘어 살아남는 요소**가 하나 있다. 액센트 색 사각형, 점, 원, 선 하나가 커서가 됐다가, 글자의 점이 됐다가, 다음 장면을 여는 패널이 된다. 관객은 이 요소를 따라가며 장면 전환을 "편집"이 아니라 "변신"으로 느낀다.

- 모티프는 하나만. 색은 액센트 1색.
- 샷 리스트의 "모티프" 열에 샷마다 모티프가 무엇을 하는지 적는다 (등장 / 커서 / 글자 일부 / 패널로 확장 / 사라짐 / 락업의 마침표).
- 모티프가 다음 샷으로 넘어가는 순간이 곧 매치 컷이다: 나가는 샷의 모티프 위치·크기 = 들어오는 샷의 모티프 위치·크기.

## 2. 페이싱 곡선

15초 모션 쇼릴의 전형 (참조 분석 결과를 우선한다):

| 구간 | 비율 | 샷 길이 | 역할 |
|---|---|---|---|
| 오프닝 | 0–25% | 1.5–2s | 세계관 세우기 (그리드, 모티프 등장). 느리게 |
| 빌드 | 25–45% | 0.8–1.2s | 핵심 단어 등장, 첫 변형 |
| 가속 | 45–65% | 0.4–0.6s (비트마다) | 변형 연타. 컷이 비트에 붙는다 |
| 브레더 / 전환 | 65–80% | 1.5–2.5s | 톤 전환 (다크 3D, 텍스처). 숨 고르기 |
| 클라이맥스 → 락업 | 80–100% | 마지막 1.5s 이상 홀드 | 이름/로고 확정, 정지 |

**같은 길이의 샷이 연속 3개 이상이면 리듬이 죽는다.** 가속 구간만 예외(비트 그리드이므로).

## 3. 비트 동기화

- `npx hyperframes beats <project>` → 비트 시각. 강한 비트(`strength ≥ 0.6`)를 컷 후보로.
- 하드 컷, 패널 닫힘, 슬램 착지 = **비트 위**. 긴 움직임(푸시 인, 드리프트)은 비트와 무관하게 흐른다.
- 모션의 **도착**을 비트에 맞춘다(시작이 아니라). `at = beat - duration`.
- 가속 구간은 1비트 또는 2비트 간격으로 고정 그리드.
- kit: `K.snap(t, beats)`로 계획 시점을 가장 가까운 비트로 스냅.

## 4. 이징 사전

| 느낌 | GSAP | 쓰임 |
|---|---|---|
| 스냅 (빠르게 와서 딱 멈춤) | `expo.out`, `power4.out` | 모션 디자인 기본 등장 |
| 가속 이탈 | `power4.in`, `expo.in` | 휩·나가는 요소 (다음 컷 직전 최고 속도) |
| 기계적 슬라이드 | `expo.inOut` | 패널, 분할 |
| 스프링 | `back.out(1.7)` | 팝, UI, 캐릭터 (모션 디자인에선 절제) |
| 선형 | `none` | 느린 푸시 인, 스크롤, 드리프트 |
| 스텝 | `steps(n)` 또는 0.001s set | 타이핑, 깜빡임, 스톱모션 |

모션 디자인 쇼릴은 **스냅과 가속 이탈의 짝**이 기본이다. 부드러운 `sine`, 과한 `elastic`은 쓰지 않는다.

## 5. 타이포 원칙

- **단어는 화면을 채운다.** 쇼릴 참조의 메인 단어는 화면 폭의 85–95%다. font-size를 눈대중으로 정하지 말고 kit `fitWidth`로 목표 폭에 맞춘다. 실제 재현 테스트에서 가장 큰 차이가 이것이었다 (고정 크기로 65% 폭 → 참조보다 확연히 약해 보임).
- 가변 폰트 하나로 굵기·너비 대비를 만든다 (Black ↔ Thin, Condensed ↔ Wide). 폰트 수를 늘리지 않는다. 기본 상태는 컨덴스드(wdth 80–90) + Black이 참조 그로테스크와 가깝다.
- 화면을 꽉 채우는 크기(화면 너비의 70–100%)와 아주 작은 라벨(12–16px 모노)의 극단 대비.
- 대문자 라틴은 자간 -2% ~ -4%. 한글은 -3% 내외, `word-break: keep-all`.
- 가변 폰트 확보: Latin은 `@fontsource-variable/archivo`(wght+wdth), `@fontsource-variable/inter`(wght). jsdelivr에서 `.woff2`를 받아 `assets/fonts/`에 두고 `@font-face` 선언 (`hyperframes-core` 규칙: 로컬 파일만). 한글은 Pretendard Variable.

```bash
V=$(npm view @fontsource-variable/archivo version)
curl -fsSL -o assets/fonts/Archivo-var.woff2 "https://cdn.jsdelivr.net/npm/@fontsource-variable/archivo@$V/files/archivo-latin-wdth-normal.woff2"
```

## 6. 색과 톤 전환

- 2색 + 액센트 1색 (예: 오프화이트 #EEEAE3 / 잉크 #111 / 오렌지 #FF4A1C). 참조에서 스포이드로 추출.
- 중간에 한 번 **톤 반전**(밝은 → 다크 3D 구간)이 브레더 역할을 한다. 반전은 하드 컷으로.
- 배경 그리드/노이즈 텍스처는 5–10% 불투명도. 정지 화면에서도 "재질"이 있게.

## 7. 3D와 셰이더

- 글자 돌출은 CSS 레이어(kit `depthText`)로 충분하다. 카메라가 글자 주위를 도는 샷만 Three.js (`hyperframes-animation/adapters/three.md`).
- 유체/노이즈 텍스처 샷은 kit `noiseField`(결정적 canvas)로 충분하다. 셰이더 블록은 데모 컴포지션이라 바로 끼울 수 없다 (shot-decomposition.md 블록 사용 메모).
- CSS 레이어 돌출은 "쌓인 두께"까지만 낸다. 참조가 원근·조명·반사 바닥이 있는 진짜 3D면 Three.js가 필요하고, 아니면 차이를 샷 리스트에 명시한다.
- 3D/셰이더 구간은 정지 프레임 게이트(G3)에서 가장 많이 틀어진다. 해당 샷은 먼저 단독 렌더로 확인한다.
- Three.js를 쓰면 [three-d.md](three-d.md)의 결정적 렌더 계약, 실측 모션 곡선, 모션 블러, 사실감 체크리스트를 따른다.

## 8. 락업

- 마지막 1.5–2s는 완전 정지. 움직임 없음.
- 워드마크 + 작은 라벨(연도, 카테고리) + 액센트 요소(마침표, 사각형)로 모티프를 마무리.
- 루프 영상이면 마지막 프레임 = 첫 프레임 (`scripts/loop_seam.py`로 검증).

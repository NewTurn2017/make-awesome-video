- 한 줄: <무엇을 누구에게>

- 영상이 끝났을 때 시청자가 기억할 한 문장: ...

## 브랜드
- 로고: assets/logo.svg
- 색: primary #...., background #...., accent #....

## storyboards/<A|B|C>.md

3안은 **방향**이 달라야 한다. 한 안이 다른 안의 다듬은 버전이면 다시 쓴다. 차이를 만드는 축: 주인공(UI vs 메시지 vs 결과물), 리듬(빠른 컷 vs 긴 연속 무브), 오프닝 훅(문제 제시 vs 결과 먼저 vs 대담한 선언), 톤.

```markdown
# Storyboard A — "<로그라인: 한 문장으로 이 안의 방향>"

방향: 참조 충실형 / UI 주인공형 / 타이포 주인공형 / ...
길이: 30s · 장면 7개 · 평균 샷 1.4s · 트랜지션: 하드 컷 위주

| # | 시간 | 화면 텍스트 | 비주얼 | 비트의 역할 | 카메라/모션 | 트랜지션 아웃 (넘겨지는 물체) | HyperFrames 블록 |
|---|---|---|---|---|---|---|---|
| 1 | 0.0–2.5 | "Stop writing release notes" | 검정 배경, 좌측 정렬 대형 타이포 | 문제 제시 | 단어별 마스크 리빌, 스태거 40ms | "notes"가 카메라 통과 → 아래 대시보드 (전경 플라이스루) | per-word-rise, zoom-through-transition |
| 2 | 2.5–6.0 | — | 실제 대시보드 스크린샷 (assets/screens/dash.png) | 제품이 하는 일 | 1.0→1.06 느린 푸시 인 | 선택된 PR 카드가 다음 장면 헤더 위치로 (선택 → 확장) | push-in, ui-focus-zoom |
| 3 | ... | | | | | | |
| 7 | 26–30 | "<제품명> — try it free" | 로고 + CTA 버튼 (21st 버튼) | 다음 행동 | 버튼에 푸시 인 + 프레스 리플 | 끝 | logo-brand-close, press-ripple |

## 시그니처 변형 3개
효과 이름 없이 설명한다. 예: "PR 카드가 펼쳐져 릴리스 노트 본문이 된다", "흩어진 커밋 목록이 한 줄 요약으로 수렴한다".
1. ...
2. ...
3. ...

## 밀도 점검
- 구도 수 / 길이 (30초 기준 12–15), 주 피사체 화면 점유 60–85%, 0.6초 넘는 무동작 구간 없음
- 모든 주장이 brief.md의 사실에 근거하는가

## 왜 이 방향인가
- 참조의 어떤 문법을 가져왔는지, 브리프의 어떤 목표를 채우는지 2–3줄

## 리스크
- 예: "장면 4는 스크린샷 해상도가 낮으면 푸시 인 시 흐려짐 → 2x 스크린샷 필요"
```

## 3안을 사용자에게 제시하는 방식

- 3안을 표로 나란히 요약 (로그라인, 오프닝 훅, 리듬, 주인공, 길이)
- 가능하면 각 안의 **핵심 장면 1개**를 정지 프레임으로 빠르게 만들어 `npx hyperframes compare`로 한 장의 비교 시트를 보여준다 (선택 사항, 시간 여유 있을 때)
- 마지막 줄: "A/B/C 중 하나, 또는 조합(예: A 오프닝 + B 데모)을 골라주세요."

## 정지 프레임 단계 (G3) 제시 방식

- 장면 번호 + 시간 + 스냅샷 경로를 목록으로
- 각 프레임에 대해 스스로 확인한 [quality-bar.md](quality-bar.md) 항목 중 걸리는 것을 먼저 밝힌다
- 사용자가 수정할 때는 장면 번호로 지시하게 유도한다: "3번: 헤드라인 더 크게, 스크린샷 오른쪽으로"

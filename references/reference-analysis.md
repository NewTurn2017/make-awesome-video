# 참조 영상 → 스타일 스펙

"이 영상처럼"이 작동하려면 참조를 **측정 가능한 규칙**으로 바꿔야 한다. 목표는 복제가 아니라 페이싱·타이포·트랜지션 문법을 빌리는 것. 참조의 로고, 카피, 고유 일러스트는 가져오지 않는다.

## 1. 기계적으로 뽑기

```bash
bash {baseDir}/scripts/analyze_ref.sh "<X URL | 유튜브 URL | 로컬 mp4>" refs/<slug>
```

출력:

- `ref.mp4` — 원본 (학습용, 결과물에 넣지 않음)
- `scores.tsv` — 프레임별 장면 변화 점수 (시간, 점수)
- `cuts.txt` — 하드 컷 타임스탬프 (점수 ≥ 임계값, 기본 0.3)
- `peaks.txt` — 변화 피크 (적응형 임계값). 모션 그래픽은 하드 컷보다 휩·와이프·모프 같은 애니메이션 전환이 많아서 하드 컷만으로는 리듬이 안 잡힌다. 페이싱은 주로 이쪽을 본다
- `stats.txt` — 길이, 해상도, fps, 하드 컷/변화 피크 각각의 수와 평균/최소/최대 비트 길이
- `contact.png` — 1초 간격 컨택트 시트
- `shots/` — 각 컷 직후 프레임 PNG
- `palette.png` — 대표 색 팔레트

컷 검출은 하드 컷에 강하고 긴 크로스페이드·연속 카메라 무브에는 약하다. 샷 길이가 비정상적으로 길면 연속 무브일 가능성이 크니 영상을 직접 보고 보정한다.

## 2. 눈으로 채우기

`contact.png`와 `shots/`를 열어 본다. 가능하면 원본을 재생해 모션을 확인한다.

## 3. `refs/style-spec.md` 형식

```markdown
# Style spec — <참조 이름> (+ <두 번째 참조>)

원본: <X 링크>  /  whatships: <디렉터리 링크>

## 한 줄 요약
예: "흰 배경 + 검정 대형 산세리프, 0.6초 하드 컷 리듬, 제품 UI 위로 느린 푸시 인"

## 페이싱
- 총 길이: 0:29 / 컷 수: 24 / 평균 샷 1.2s (최소 0.4, 최대 3.1)
- 구조: 훅 0–3s → 문제/약속 3–8s → 기능 데모 8–22s → 로고+CTA 22–29s
- 리듬 규칙: 텍스트 비트는 0.5–0.8s, UI 데모는 2–3s 유지

## 타이포
- 서체 계열: 기하학 산세리프 / 굵기 700–800 / 자간 -2%
- 크기: 헤드라인이 화면 높이의 약 12–18%
- 대소문자: sentence case, 마침표 없음
- 배치: 좌측 정렬, 안전 영역 8% 마진 (중앙 정렬 아님)
- 텍스트 등장 방식: 단어별 아래→위 마스크 리빌, 스태거 40ms

## 색 & 배경
- 배경: 단색 #0B0B0C (그라데이션 없음)
- 액센트: 1색만, 강조 단어와 커서에만
- 대비 규칙: ...

## 트랜지션
- 기본: 하드 컷 (전체의 ~80%)
- 특수: 섹션 전환 2회만 whip pan / match cut
- 금지: 크로스페이드, 디졸브

## 카메라 & 모션
- UI 장면: 1.0→1.06 느린 푸시 인 (샷 전체 길이 동안, ease out)
- 이징 느낌: 강한 ease-out (expo/quart), 오버슈트 없음 / 또는 스프링 오버슈트 약간
- 모션 블러: 있음/없음

## UI 표현
- 실제 스크린샷 / 브라우저 크롬 유무 / 디바이스 프레임 유무
- 커서: 크게, 클릭 시 리플

## 사운드
- 음악 장르, 컷이 비트에 맞는지, SFX(클릭, 휘시) 유무

## 우리 영상에 가져올 것 / 가져오지 않을 것
- 가져옴: 페이싱, 좌측 정렬 타이포, 하드 컷 비율
- 안 가져옴: 참조의 색(우리 브랜드 색 사용), 참조의 3D 일러스트
```

## 4. 참조 2개를 섞을 때

역할을 나눈다. 예: "페이싱·트랜지션은 A, 타이포·색 처리는 B". 두 참조가 같은 축에서 충돌하면 사용자에게 어느 쪽인지 묻는다.

## 5. 스타일을 이름으로 부르는 어휘

스펙 한 줄 요약에 쓰면 좋은 이름들 (설명보다 이름이 강하다):

- **Swiss / International grid** — 엄격한 그리드, 대형 산세리프, 좌측 정렬, 원색 액센트 (HyperFrames 예제 `swiss-grid`, `vignelli`)
- **Kinetic type** — 단어가 박자에 맞춰 슬램/스왑 (`kinetic-type`, `headline-slam`, `kinetic-type-swap`)
- **Apple keynote product** — 검정 배경, 제품 클로즈업, 느린 푸시 인과 라이트 스윕 (`light-sweep-pass`, `push-in`, `vfx-iphone-device`)
- **Linear/Vercel-style dark UI** — 다크 UI, 미세한 글로우, 정밀한 UI 줌 (`ui-focus-zoom`, `browser-device-stage`)
- **Warm editorial / film grain** — 따뜻한 톤, 그레인, 세리프 (`warm-grain`, `grain-overlay`)
- **Hand-drawn / whiteboard** — 손글씨 주석, 스크리블 (`hw-*` 블록)
- **Data story** — 차트가 주인공 (`nyt-graph`, `data-chart`, `chart-story`)

HyperFrames 이름은 `npx hyperframes catalog --json`으로 현재 존재하는지 확인하고 쓴다.

# 크리틱 루프: 만든 사람이 채점하지 않는다

빌더는 자기 결과물의 결함을 반복해서 놓친다. 실제 제작에서 빌더의 체크가 전부 통과한 36초 영상이, 새 크리틱이 재보니 10초가 사실상 정지 화면이었다. 그래서 **렌더를 사용자에게 보여주기 전에** 맥락을 모르는 새 에이전트가 실제 픽셀과 측정값으로 판정한다. 이 루프는 G1–G4 게이트를 대체하지 않는다. 게이트에 들고 가는 결과물의 수준을 올리고, G4의 "노트 초안"을 만든다.

출처: [motion-video-kit](https://github.com/echris6/motion-video-kit)의 Gauntlet 루프(MIT)를 이 스킬의 게이트 구조에 맞춰 옮겼다.

## 규칙

1. **빌더 ≠ 판정자.** 판정마다 **새** 서브에이전트(Claude Code는 `Agent` 도구, Codex는 새 세션)를 띄운다. 이전 크리틱을 재사용하지 않는다.
2. **크리틱에게 주는 것은 네 가지뿐:** 결과물 경로(MP4 또는 스냅샷 폴더), `brief.md`, `refs/style-spec.md`(와 참조 영상 경로), 검증 라운드라면 이전 크리틱 보고서. **내가 무엇을 고쳤는지, 왜 이렇게 만들었는지는 주지 않는다.** 크리틱이 스스로 찾아야 한다.
3. **픽셀과 수치로 판정한다.** 크리틱은 프레임을 직접 뽑고(`scripts/contact_sheet.sh`, 전환마다 1/30초 밀도 창), `scripts/frozen_time.sh`와 `scripts/loudness.sh`를 돌린다. 의도는 판정 근거가 아니다.
4. **가장 큰 결함부터.** 다른 장면이 좋다고 약한 오프닝이 상쇄되지 않는다.
5. **고쳤다고 가정하지 않는다.** 다음 라운드는 또 다른 새 크리틱이 이전 항목을 하나씩 FIXED / PARTLY / STILL PRESENT로 확인하고 회귀를 찾는다. 수정은 새 결함을 자주 만든다 (덮인 요소의 z-order 상실, 옮긴 요소가 헤드라인을 가로지름, 한 곳의 안전 영역 클램프가 2초 뒤 충돌을 만듦).
6. **멈춤 조건:** [quality-bar.md](quality-bar.md)를 통과하거나, 남은 항목이 서브프레임·미세 조정뿐이거나, 사용자가 그만이라고 할 때. 라운드 수로 멈추지 않는다 (보통 전체 영상 기준 2–4라운드).
7. **원장을 남긴다.** `<project>/review/ledger.md`에 한 줄씩: 라운드 → 결과물 → 크리틱 핵심 지적 → 바꾼 것 → 측정 전/후. 완료 보고에 그대로 쓴다.

## 게이트별 라운드

| 언제 | 라운드 | 결과물 | 크리틱 초점 | 필수 여부 |
|---|---|---|---|---|
| G2 제시 전 | 스토리보드 | 3안 또는 `shots.md` | 사실성(주장·수치가 참인가), 장면마다 구도와 역할이 다른가, 필러 비트, 음소거 상태에서 CTA가 분명한가 | 선택 (`launch` 30초 이상이면 권장) |
| G3 제시 전 | 정지 프레임 | `snapshots/` (`motion`은 `--against` 쌍) | 레이아웃, 여백 낭비, 글자 충돌·잘림, 브랜드 색, 참조 대비 차이 | 권장 |
| 3D·커스텀 컴포넌트 합류 전 | 컴포넌트 | 단독 렌더(정지 3장 + 3–4초 모션 증명) | 재질, 카메라, 팝(한 프레임 튐), 충돌, 이 컴포넌트가 주는 정보 | 해당 시 필수 |
| G4 제시 전 | 전체 영상 | `renders/*.mp4` | 정지 구간, 빈 화면, 전환, 글자 충돌, 페이싱, 사업 메시지, 오디오 | **필수** |
| G4 반복마다 | 검증 | 새 렌더 + 이전 보고서 | 항목별 상태 + 새 회귀 + SHIP / ONE MORE PASS | **필수** |

전체 영상 크리틱의 상위 지적은 SKILL.md 6단계의 "에이전트가 먼저 제안할 노트"가 된다. 크리틱 보고서를 그대로 붙이지 말고, [director-notes.md](director-notes.md) 카메라 어휘로 3–5개 노트 초안으로 바꿔 사용자에게 제시한다. 사용자의 노트가 크리틱과 다르면 **사용자가 우선**이다.

## 크리틱 프롬프트

`<>`를 채워 새 에이전트에 보낸다. 내 추론은 넣지 않는다. 보고서는 `<project>/review/` 아래에 파일로 쓰게 한다.

### 전체 영상 크리틱

```
너는 독립 크리틱이다. 이 영상을 만들지 않았다. 의도가 아니라 렌더된 픽셀과 측정 가능한 오디오로 판정하라. 가혹하게.

결과물: <path>.mp4 (<길이>s, <해상도>, <fps>fps, 오디오 <있음/없음>)
브리프: <project>/brief.md   스타일 스펙: <project>/refs/style-spec.md   참조 영상: <refs/slug/ref.mp4>
<이전 컷이 있으면> 이전 렌더: <path>, 이전 보고서: <path>. 어떤 지적이 해결됐는지도 확인하라.
사용자 기준 (원문 그대로): <사용자가 한 말>

방법:
- bash {baseDir}/scripts/contact_sheet.sh <mp4> <scratch>/sheet.jpg 0.25 8 6  (길면 구간을 나눠 여러 장)
- 전환 시점마다 1/30초 밀도 창: contact_sheet.sh <mp4> <scratch>/t<시각>.jpg 0.0333 6 3 <시각-0.3> 0.6
  전환 시점: <컷 시각 목록>
- bash {baseDir}/scripts/frozen_time.sh <mp4> --ignore-tail <락업 길이>
- 오디오가 있으면 bash {baseDir}/scripts/loudness.sh <mp4>, 소리가 화면 사건에 맞는지 확인
- 이미지를 직접 열어 보고, 필요한 곳은 크롭해서 본다

보고서(900단어 이내)를 <project>/review/round-<n>-film.md 에 쓰고 요약을 답하라:
1. 장면별: 시간 범위, 화면 내용, 빈 화면 비율(%), 줄일 수 있는 초, 문제(심각도순)
2. 레이아웃·전환 결함 (타임스탬프, 화면 영역)
3. 측정값: 정지 구간 총합과 최장 홀드, LUFS/LRA/true peak
4. 영향이 큰 순서로 구체적이고 구현 가능한 변경 6–8개
군더더기 없이.
```

### 검증 크리틱

```
너는 독립 크리틱이다. 이 영상을 만들지 않았다.
결과물: <새 렌더>. 이전 크리틱 보고서: <path>. 장면 타이밍이 약 <x>s 이동했다 (<새 장면 지도>).

이전 보고서의 상위 변경과 결함 각각에 FIXED / PARTLY / STILL PRESENT를 타임스탬프와 함께 판정하라.
그다음 새 결함을 찾아라: 글리치 프레임, 겹침, 잘린 글자, 어색한 전환 중간 프레임, 새로 생긴 정지 구간.
방법은 전체 영상 크리틱과 같다 (contact_sheet.sh, frozen_time.sh, loudness.sh).
<project>/review/round-<n>-verify.md 에 500단어 이내로 쓰고, 마지막 줄은 SHIP 또는 ONE MORE PASS (최대 3개 수정).
```

### 정지 프레임 / 컴포넌트 크리틱

```
너는 독립 시각 크리틱이다. 이 결과물을 만들지 않았다. 렌더된 픽셀만 판정하라.
결과물: <snapshots 폴더 또는 proof.mp4>. <무엇을 전달해야 하는지 한 문장>. 브랜드: <HEX>, <서체>.
<이전 버전이 거절된 이유가 있으면 사용자 말 그대로>
기준: 프리미엄 런치 영상 (주 피사체가 화면을 채움, 여백 낭비 없음, 읽히는 정보).
디테일을 크롭해서 봐라: 이음새, 재질, 라벨 가독성, 핀·콜아웃이 가리키는 대상의 정확성, 충돌, 팝.
<project>/review/<name>.md 에 450단어 이내: 판정 KEEP / REVISE / REJECT, 심각도순 결함(타임스탬프·영역), 코드로 구현 가능한 최우선 수정 3개.
```

### 스토리보드 크리틱

```
<길이>s <제품/브랜드> 영상의 스토리보드다. 너는 이걸 쓰지 않았다. <storyboards/*.md 또는 shots.md>와 brief.md를 읽고 점검하라:
실제 제품·서비스가 작동하는 순서와 맞는가, 모든 주장이 사실로 증명 가능한가(브리프에 없는 수치·후기·성과가 있는가),
비트마다 구도와 역할이 다른가, 어떤 비트가 필러인가, 소리를 끄고 봐도 무엇을 하는 회사이고 다음 행동이 무엇인지 알 수 있는가.
문제를 심각도순으로, 각각 구체적 수정 하나와 함께.
```

## 원장 형식 (`review/ledger.md`)

```markdown
| 라운드 | 결과물 | 크리틱 핵심 지적 | 바꾼 것 | 측정 전 → 후 |
|---|---|---|---|---|
| film-1 | renders/v1.mp4 | 정지 6.5s, 2.8s 장면 빈 화면 60% | 장면 3 삭제, 장면 5 푸시 인 추가 | 정지 6.5s → 1.1s |
| verify-2 | renders/v2.mp4 | 7개 중 5 FIXED, 12.4s 제목이 와이프에 잘림 | 제목이 와이프 전에 퇴장 | — |
```

## 실제로 크리틱이 잡은 것 (빌더는 놓침)

- 레이어가 들어 올려지기 시작할 때 한 프레임 "팝": 시작 속도가 최대인 ease-out. 고침: smootherstep + 미세 스태거.
- 와이프가 두 제목을 한 단어로 이어 붙임 ("Sur|ctions."). 고침: 나가는 제목은 와이프 전에 퇴장, 들어오는 제목은 와이프 후 등장.
- 거의 수직 하강 카메라가 집을 평평한 판으로 만들고 텍스처 반복이 보임. 고침: 피치 35–55°, 최소 거리.
- 상태 전환 사이 0.2초 동안 카드가 빔. 고침: 내용을 제자리에서 크로스페이드.
- 이동 중인 글자가 다른 글자를 관통. 고침: 페이드 아웃 후 목적지에서 페이드 인.
- 부모가 느린 스케일 푸시 중이라 유지되는 헤딩이 12px 어긋남. 고침: 오버레이에도 같은 푸시.
- 한 트윈이 두 캡션 변형을 동시에 잡아 사진에 틀린 라벨.
- 장르 전환 지점의 순수 검정 3프레임, 락업 푸시가 작은 표기를 가장자리 31px까지 밀어냄.
- 증상 뒤의 원인: 거의 무음인 음악 기준으로 계산한 효과음 게인, 33ms 앞 여백이 있는 샘플 때문에 모든 타격이 2프레임 늦음.
